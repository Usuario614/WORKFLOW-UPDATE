WORKFLOWPROOF · SAMPLE AUDIT

Will every valid lead reach the CRM?

Pre-release review of a synthetic n8n workflow. The findings below come from the WorkflowProof engine. The workflow was reviewed as an export.

Release recommendation. Validate duplicate handling and recovery before handoff. Confirm that a valid lead creates exactly one CRM record, an invalid lead creates none, and a failed write is visible to the team.

What the export shows

HIGH · External side effects lack visible recovery path

1 external action node(s) have no obvious retry or recovery strategy.

Write lead to CRM
HIGH · Webhook can reach side effects without visible deduplication

Webhook can repeat 1 operational side effect(s) without an obvious idempotency guard.

Inbound lead
MEDIUM · HTTP call has no explicit timeout hint

No explicit timeout configuration was found in this HTTP node.

Write lead to CRM

What changed on re-review

Set a 10-second timeout on Write lead to CRM for this sample. The timeout finding cleared. The score stayed at 79 → 79 with 4 open High findings. Confirm the timeout with the provider and establish whether a write can be retried safely.

Three checks to run in staging

  1. Valid and invalid input. Send each to the staging workflow. Verify one CRM record for the valid lead and zero for the invalid lead.
  2. Duplicate delivery. Deliver the same event twice. Confirm the CRM contains exactly one record for that event.
  3. Ambiguous failure. Simulate a CRM response timeout after recording the lead. Verify the team sees the failure and that recovery does not create another record.

These are proposed checks with expected outcomes. No staging execution is included in this sample.
